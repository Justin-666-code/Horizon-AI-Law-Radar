# 个人 AI × 法律 × 公共服务雷达

## Why

订阅者是一名人工智能专业本科生，计划继续攻读法律硕士并关注定向选调生等公共服务机会。现有 Horizon 默认配置偏向通用科技新闻，无法稳定区分 AI 研究、法律治理、法硕招生和选调公告，也无法按截止日期安排阅读优先级。

目标是在不修改 Horizon 业务代码的前提下，提供一套可直接部署的个人信息雷达，降低每日筛选成本，并保留每条信息的原始链接供人工核验。

## What

- 每天收集中文 AI 动态、AI 研究、AI 法律与治理、法硕招生、选调生与公务员招录信息。
- 将内容分为五个阅读域：机会公告、法律治理、AI 研究、AI 产品与产业、工程实践。
- 每个域使用独立评分标准；机会公告优先展示截止日期和下一步行动。
- 默认只生成中文简报，控制模型成本。
- 默认通过 GitHub Actions 每日采集并发布到 GitHub Pages；本地运行作为备用方式。
- 所有输出保留原始来源链接，关键公告必须由用户回到官方页面确认。

## Constraints

- 不修改 Horizon 上游 Python 业务逻辑。
- 密钥只存放在本地 `.env` 或 GitHub Actions Secrets，不进入 Git、配置样例或聊天记录。
- 默认模型为阿里云百炼 `qwen-plus`，只需要 `DASHSCOPE_API_KEY`。
- 默认关闭邮件、微信和 Webhook，避免首次部署引入额外凭据。
- Google News RSS 是法律和公共服务信息的主要发现入口；该源在部分本地网络可能不可用，因此以 GitHub Actions 为主要运行环境。
- AI 不得推断报考资格、法硕政策或法律生效状态；不确定信息必须省略或明确标注。
- 单日简报最多 18 条，避免一次运行产生不可控的 API 成本。

## Out of Scope

- 不替用户报名、择校、选岗或提供法律意见。
- 不自动抓取任何需要登录、验证码或付费订阅的页面。
- 不对官方公告做录取概率、资格结论或政策预测。
- 本阶段不启用 X/Twitter、OpenBB、邮件、微信和 Webhook。

## Decisions

- 采用“配置 + profile + 工作流”的个人层，而不是 fork 业务代码，便于以后合并上游更新。
- 对 arXiv 使用带 `max_results` 的 Atom 查询，而不是全量分类 RSS，避免每天数百篇论文消耗模型额度。
- 对无稳定 RSS 的国内公告使用限定关键词的 Google News RSS 查询；在 GitHub Actions 中运行，并通过原文链接复核。
- 中文单语输出优先于双语输出，以降低约一半的生成成本和阅读噪声。
