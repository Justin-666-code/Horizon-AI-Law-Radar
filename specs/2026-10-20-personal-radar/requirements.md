# 个人 AI × 法律 × 公共服务雷达

## Why

订阅者目前是人工智能本科二年级学生，需要先建立数学、编程、模型训练与评测基础。法律硕士和公共服务是后续方向，不应在现阶段占据每日注意力。

目标是在不修改 Horizon 业务代码的前提下，提供一套可直接部署的个人信息雷达，降低每日筛选成本，并保留每条信息的原始链接供人工核验。

## What

- 每天收集一手 AI 研究、官方项目更新、基础学习内容与工程实践。
- 将默认内容分为四类：AI 基础与动手实践、AI 研究、AI 产品与产业、工程实践。
- 每个域使用独立评分标准；基础内容优先展示学习重点、先修知识和可执行练习。
- 将法律、知识产权、数字政府、政务 AI 和公共部门法律实践合并为低配额融合线；不追踪招考。
- 默认只生成中文简报，控制模型成本。
- 默认通过 GitHub Actions 每日采集并发布到 GitHub Pages；本地运行作为备用方式。
- 每天将 `gh-pages` 中当天的中文日报同步到 `D:\知识库\knowledge1`，文件名为 `horizon-YYYY-MM-DD-zh.md`。
- 所有输出保留原始来源链接，关键公告必须由用户回到官方页面确认。

## Constraints

- 不修改 Horizon 上游 Python 业务逻辑。
- 密钥只存放在本地 `.env` 或 GitHub Actions Secrets，不进入 Git、配置样例或聊天记录。
- 默认模型为阿里云百炼 `qwen-plus`，只需要 `DASHSCOPE_API_KEY`。
- 默认关闭邮件、微信和 Webhook，避免首次部署引入额外凭据。
- 默认 `information_policy` 为 `mixed`；AI 与计算机只使用一手源，融合治理允许 2 条受限发现。
- 一手不等于正确：arXiv 必须标明预印本，机构博客必须保留机构自述属性。
- 单日简报最多 10 条，避免前沿论文和产品发布挤占基础学习。
- 本机同步必须幂等；同一日期内容未变化时不得重写文件或改变修改时间。
- 日报日期必须由 `HORIZON_TIMEZONE` 决定，默认保持 UTC；本部署使用 `Asia/Shanghai`，不得按 Runner 的 UTC 日期跨日覆盖前一天文件。

## Out of Scope

- 不替用户报名、择校、选岗或提供法律意见。
- 不自动抓取任何需要登录、验证码或付费订阅的页面。
- 不对官方公告做录取概率、资格结论或政策预测。
- 本阶段不启用 X/Twitter、OpenBB、邮件和 Webhook；微信仅通过本机 iLink 会话投递。

## Decisions

- 采用“配置 + profile + 工作流”的个人层，而不是 fork 业务代码，便于以后合并上游更新。
- 对 arXiv 使用带 `max_results=12` 的 Atom 查询，日报中最多保留 3 条研究。
- 用户日常只编辑 `data/radar-preferences.json`，由生成器编译为运行配置。
- 中文单语输出优先于双语输出，以降低约一半的生成成本和阅读噪声。
- 云端不能直接写用户电脑的 `D:` 盘，因此由本机定时自动化从 `gh-pages` 拉取，而不是在 Actions 中假装写本地路径。
- 微信会话属于本机凭据，只在本机投递器中使用，不进入 GitHub Actions。
